기본 영문·숫자·원래 물음표·버튼 아이콘 슬롯은 유지했다. 사용한 6개 확장 문자 코드는 이전에 추출한 문자열 후보 자료에는 등장하지 않았지만 전체 문자열 분모는 아직 확정되지 않았으므로 전체 게임의 충돌 없음은 주장하지 않는다. 이 매핑은 PoC 전용이며 정식 문자 배정으로 채택하지 않는다.

## 정확한 변경 경계

1. 복호화 EBOOT ELF 파일 `0x1CADBC`의 `What happened?\0` 14 bytes를 `D0 9C 20 8C AE C6 99 00 00 00 00 00 00 00`로 치환했다. NUL 전 7 bytes로 원본 영역 및 확인된 31-byte 복사 제한 안에 들어간다.
2. 복호화 ELF의 나머지 모든 바이트와 실행 명령은 원본 복호화본과 동일하다. ISO에는 이 ELF를 원래 EBOOT 파일 길이까지 0으로 패딩해 넣었다. 암호화 원본과 복호화본의 차이는 첫 문장 수정과 구별해 기록한다.
3. GLOBAL_00.PXD의 픽셀 시작 `0x298D0`(170192), UIENGINE_99.PXD의 `0xEEAC0`(977600)에서 175,088-byte mip 데이터에 6개 글리프를 반영했다. 팔레트와 나머지 구조는 보존했다.
4. UI_BINARY.STR의 `0x1109C0`에 두 PXD와 바이트 단위 동일한 원본 폰트 mip 블록이 있어 함께 반영했다. 이 복사본이 실제 런타임에 언제 사용되는지는 아직 장면 검증 대상이다.
5. GLOBAL_BINARY.STR의 글리프 메트릭 6개에서 폭 float만 갱신했다. 코드 매핑과 저장 포인터는 변경하지 않았다.

10개 mip의 크기는 256×512부터 1×1까지이며 작은 mip의 행 stride는 최소 16 bytes이다. 기본 이미지에서는 6칸 밖 픽셀이 바뀌지 않았고, 하위 mip에서는 변경 글리프의 필터 영향 범위만 갱신했다. 다른 글자까지 포함한 최종 화면의 동등성은 실행으로 확인해야 한다.

모든 변경은 원본 ISO 복사본의 기존 파일 extent 안에만 적용했다. 파일 길이·디렉터리·LBA·ISO 전체 길이는 유지했다. 새 컨테이너 재구성이나 섹터 재배치는 하지 않았다.

## 검증

- 원본 ISO, 선택된 추출 입력 파일, 복호화 ELF, 지정 TTF의 기준 SHA-256 확인.
- 선택 글리프 코드/슬롯/좌표/폭의 예상 원본값 확인. 폰트 cmap에 필요한 문자가 없으면 중단.
- 기본 이미지의 6개 사각형 바깥 픽셀 동일, 10개 mip의 무수정 decode→encode 바이트 일치.
- 수정 mip encode→decode 일치. 3개 자산에 들어간 원본 폰트 블록 전체의 동일성 확인 후 같은 변경 적용.
- ISO의 논리 파일 86개 전체를 대조. 변경 5개는 계획한 최종 해시와 일치, 나머지 81개는 원본 해시와 일치.
- 등록한 5개 ISO 파일 범위 바깥의 모든 바이트를 원본과 비교해 일치 확인. 원본 파일은 수정하지 않았다.
- 최종 양자화된 글리프로 만든 미리보기를 직접 열어 문구·누락·잘림을 확인했다.
- **게임 부팅·실제 대사 표시·전환·세이브·전체 플레이는 미검증.** 배포 패치는 만들지 않았다.

## 재현

기존 환경: Python 3.12, Pillow 12.3.0, fonttools 4.63.0. 원본 폰트 경로는 프로젝트 기준 `../../Font/KyoboHandwriting2019.ttf`.

```powershell
python .\scripts\build_firstline_poc.py --prepare
python .\scripts\build_firstline_poc.py --build
```

`--build`는 기존 ISO가 있으면 보존하고 중단한다. 수정 빌드는 새 빌드 ID/출력 경로를 지정하도록 코드를 갱신한 뒤 원본에서 재생성한다. 원본 분해·복호화 준비 명령은 INITIAL_SURVEY와 인계 문서에 있다.
