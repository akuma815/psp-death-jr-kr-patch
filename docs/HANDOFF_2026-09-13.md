## 005 폰트 래스터 연결 수정 — 실제 실행으로 원인 확인

004의 글자 색 노이즈는 추가 코드가 폰트 리소스의 래스터를 RwTexture 래퍼로 잘못 해석한 결함이다. 이전 문서의 `resource[4] -> RwTexture -> raster` 설명을 폐기한다. 실제 연결은 `font[0] -> holder[0] -> resource[4] -> RwRaster`이며 raster[0]은 parent이고 root raster는 자기 자신을 가리킨다.

PPSSPPWindows64 v1.20.4-1758-g70bab7f25c에서 004 ISO 경로와 PID 21012를 version 응답으로 확인하고 원본 draw VA 0xCD194 및 driver bind VA 0x194EA8에서 중단했다. 원본 font=0x08CAB220, holder=0x08CAB240, resource=0x08CAB260, resource+0x10=0x08C827B0이고 이 주소의 첫 워드도 자기 자신이다. 원본 래스터 확장 오프셋은 52 bytes다.

004는 88 bytes만 복사한 가짜 texture 객체 0x08BA2BB0를 bind의 a1로 넘겼다. 이 객체는 원본 픽셀 0x0417EDE0/팔레트 0x041A99D0 및 256×512 정보를 그대로 담고 있었다. 실제 새 한글 래스터는 그 첫 워드로만 연결돼 있었다. bind는 a1 자체를 래스터 상태로 저장하므로 추가 간접 참조를 하지 않는다. 따라서 새 한글 metrics와 다른 텍스처 주소/크기가 결합하고, 52+80/84 위치의 native format/swizzle 또한 객체 범위 밖의 이웃 데이터가 된다. 이것이 색 노이즈를 설명하는 확인된 코드 결함이다.
