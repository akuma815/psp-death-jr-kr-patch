# 폰트 크기 측정 — 2026-09-13

## 제작 기준 권장

**한글 글자 본체를 24×24px 안에 제작하는 것을 우선 권장한다.** 1px 외곽선을 넣으면 최대 26×26px이며, 현재 렌더러의 공통 높이 31px 안에 여유를 둘 수 있다. 기존 영문 대문자의 실제 잉크 높이 22~23px와도 크게 벌어지지 않는다.

이 값은 실제 래스터 글자 본체의 픽셀 경계 기준이다. TTF의 `size=24`나 24pt가 반드시 같은 잉크 크기를 뜻하지 않으므로, 폰트 선택 후 실제 래스터 경계를 다시 확인한다. 외곽선은 적용할 경우의 예산이며 아직 스타일이나 폰트는 채택하지 않았다.

현재 구조에서 32×32px 글자를 그대로 넣는 것은 렌더링 높이 31px를 초과한다. 28px 등의 더 큰 본체도 높이상 후보가 될 수 있지만 기존 글자보다 커지고 여백이 줄어든다. 첫 후보는 24px로 두고 화면에서 가독성을 확인하는 편이 적절하다.

**31×31px 고정 셀이 원래 존재하는 것은 아니다.** 이 폰트는 가변폭이다. 영문 슬롯을 그대로 두면 대부분 24px 폭의 한글이 들어가지 않으므로 atlas 재배치와 폭·좌표 정보 갱신이 필요하다. 한글 글자 수를 수용하는 방법은 별도 과제다.

## 이미지와 렌더러를 연결한 근거

- 입력 원본과 복호화 ELF는 기존 인계 문서의 동일 리비전이다. 측정 입력 SHA-256은 `font_measurement.json`에 기록했다.
- `GLOBAL_BINARY.STR` 파일 `0x2F4`의 저장 포인터 `0x08CAB220`은 파일 `0x1CA20`의 폰트 객체와 연결된다. 이 대응의 저장 주소 기준은 `0x08C8E800`이다.
- 폰트 객체 `+0x04`는 코드 매핑, `+0x08`은 글리프별 12-byte 좌표/폭 레코드, `+0x0C`는 높이 31.0, `+0x10`은 512.0, `+0x14`는 256.0이다. `+0x18`은 208이다.
- 매핑은 파일 `0x1D470`, 글리프 좌표/폭은 `0x1CAA0`이다. 208개 레코드 모두 PNG 구분선으로 측정한 칸과 일치했다.
- 각 칸의 왼쪽 구분선 x를 L, 위쪽 구분선 y를 T, 오른쪽을 R이라 하면, 원본 px로 환산한 시작은 `(L+1.5, T+2.5)`, 폭은 `R-L-2.5`, 높이는 31이다. 행 마지막 구분선 직전까지 사용한다.
- 두 PXD에서 추출한 GLOBAL/UIENGINE atlas의 디코딩 RGBA 전체도 동일했다.
- ELF 상대 VA `0x12F590..0x12F5AC`에서 공통 상태 `+0x2F4`의 폰트 포인터와 텍스트를 `0xCD194`에 전달한다.
- `0xCD244..0xCD28C`에서 폰트 객체의 높이·텍스처 크기와 코드→글리프→폭 정보를 읽는다. `0xCD310`에서 높이/텍스처 높이로 UV 높이를 만들고 `0xCD46C..0xCD474` 등에서 공통 높이만큼 정점 높이를 만든다.
- 근거 코드: `work/analysis/font_render_measurement.disasm.txt`. 주소는 ELF 상대 VA이며 파일 오프셋은 이 영역에서 VA+0x80이다. 국소 MIPS32 명령만 해석했다.

## 화면 크기와의 구분

메뉴 렌더러는 항목별 크기 값에 0.001을 곱한 행렬을 만든다(`0x12F408..0x12F460`). 예를 들어 Paused 제목은 5.0, Options/Restart/Save 등은 약 3.1이다. Text1~Text4로 정의된 여러 본문 레코드도 약 3.1을 사용한다. 텍스트 위치와 크기는 서로 다른 계수로 변환되고 투영 경로를 거친다.

따라서 **24px 제작 글자가 게임 화면에서도 정확히 24px 높이로 보인다는 뜻은 아니다.** 이번 측정은 atlas·글리프 메트릭·국소 렌더 코드의 정적 조사다. 실제 화면 배율, 필터링, 작은 한글의 가독성, 전체 화면별 잘림은 PPSSPP 장면 검증 전까지 미확인이다.

참고로 렌더러에는 0xFF를 만났을 때 상위 바이트 상태를 변경한 뒤 16비트 코드로 조회하는 경로도 관찰됐다. 이것만으로 한글이 이미 지원된다고 결론 내리지는 않는다. 향후 코드 공간/매핑 분석의 출발점으로만 남긴다.
